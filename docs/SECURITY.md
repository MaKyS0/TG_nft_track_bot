# Безопасность NFT Tracker

Документ отвечает на вопрос «можно ли что-то украсть» и честно разделяет **проверенное** и **непроверенное**.
Это самопроверка автора кода (автоматические инструменты, тесты «глазами атакующего», разбор кода), а **не независимый пентест**.

## Что нужно защищать

| Секрет / данные | Что даёт злоумышленнику | Где лежит |
|---|---|---|
| `BOT_TOKEN` | полный контроль над ботом: читать сообщения пользователей, писать от имени бота, менять профиль, подделывать вход в мини-приложение | `.env` |
| `TG_SESSION_STRING` | **полный контроль над служебным аккаунтом Telegram** (читать чаты, отправлять сообщения, распоряжаться подарками аккаунта) | `.env` |
| `TG_API_HASH` | само по себе почти безвредно, но вместе с сессией упрощает работу атакующего | `.env` |
| База (`data/gifts.db`) | Telegram ID, username, имя и фильтры пользователей бота. Паролей и кодов входа нет | `data/` |

## Что проверено и как

| Проверка | Результат |
|---|---|
| **bandit** (статический анализ `app/`, `scripts/`) | нашёл 6 замечаний, все исправлены: невидимые управляющие символы в исходнике (стиль «trojan source»), SHA-1 без пометки «не для безопасности» (×2), сервер слушал все интерфейсы по умолчанию, `assert` в рабочем коде, `random` в демо-источнике. Повторный запуск чист |
| **pip-audit** (известные уязвимости в зависимостях) | в установленном окружении уязвимостей нет (на день проверки). Версии в `requirements*.txt` заданы диапазонами, не хэшами |
| **Поиск секретов** в коде и всей истории git | токенов и сессий нет; `.env`, `*.session`, `*.db`, `data/` в `.gitignore` |
| **Атакующие тесты** (`tests/test_security.py`, 40+ случаев) | см. ниже |
| Весь набор тестов | 190 тестов, SQLite и PostgreSQL |

### Что именно пытались сломать (и не вышло)

* **Чтение файлов через веб-сервер**: 12 вариантов обхода пути (`..`, `%2e%2e`, двойное кодирование, `\`, нулевой байт, абсолютные пути, `/.env`, `/data/gifts.db`): везде 400/403/404, содержимое не отдаётся. Листинга каталогов нет.
* **Выдача себя за другого пользователя**: подмена `user` в подписи, дописывание полей, чужой токен бота, просроченная и «будущая» подпись, `?user_id=`, заголовки: везде 401 или игнорируется. Пользователь определяется только проверенной подписью Telegram.
* **Доступ к чужим фильтрам** (IDOR): 404; проверено и в боте (подделка `callback_data`), и в API.
* **SQL-инъекции** (`'; DROP TABLE…`, `OR 1=1`, `DELETE FROM users`) в поля фильтров: сохраняются как обычный текст, таблицы целы (запросы параметризованы).
* **HTML/XSS-инъекции**: данные от пользователей и **сторонних рынков** (названия, имена владельцев, фильтры) экранируются в сообщениях бота и выводятся через `textContent` в мини-приложении. Ссылки строятся только из наших шаблонов по проверенным шаблонам (`slug`, `@username`); кнопки ведут только на `t.me`.
* **Нагрузка**: тело запроса > 16 КБ отклоняется (413); лимит запросов на пользователя (30 в пачке, 5/с); лишние методы (405); у бота троттлинг обновлений и общий лимит отправки.
* **Утечки**: 500-е ошибки не раскрывают детали; ответы API не содержат токенов и подписей; баннер сервера скрыт; токен маскируется в логах; ошибки валидации конфигурации не печатают введённый токен (это нашёл тест, исправлено); `repr` настроек не раскрывает секреты; ответы MRKT не пишутся в лог вместе с токеном.
* **Недоверенные данные рынков**: тексты очищаются от управляющих и bidi-символов и обрезаются, числа проверяются по типу и диапазону, размер ответа ограничен 2 МБ, мусорные ответы дают понятную ошибку, а не падение.

## «Можно ли украсть данные с моего планшета?»

Разбор по сценариям (кто атакует и что получит):

| Сценарий | Вывод |
|---|---|
| **Кто-то из интернета** находит адрес туннеля | видит только статическую страницу; API требует подпись Telegram. Файлы прочитать нельзя (тесты выше). Токен подделать подпись не позволяет без самого токена. Остаётся шум/нагрузка: Cloudflare перед туннелем и лимиты на пользователя это смягчают |
| **Другое приложение на планшете** | без root не может читать закрытую папку Termux (`/data/data/com.termux`). Порт `127.0.0.1:8080` доступен приложениям, но без подписи бесполезен |
| **Человек с вашим разблокированным планшетом** или root/ADB | **получит всё** (`cat .env`). Защита: блокировка экрана, шифрование хранилища (по умолчанию в современном Android), не оставлять разблокированным |
| **Утечка токена бота** (он был опубликован в переписке) | **самый реальный риск сейчас.** Любой, кто его увидит, управляет ботом. **Нужно `/revoke` в @BotFather** и новый токен только в `.env` |
| **Утечка строки сессии** | захват служебного аккаунта. Поэтому: отдельный аккаунт без ценностей, 2FA, строка не печатается на экран (скрипт пишет прямо в `.env`), `.env` с правами 600. **Не присылайте мне скриншоты с `.env`, логами входа или сессией** |
| **История буфера обмена** клавиатуры | вставленный токен/`api_hash` может сохраняться. Очистите буфер после ввода |
| **Подмена пакетов** (pip/pkg) | риск есть у любого проекта: зависимости не закреплены хэшами. На день проверки `pip-audit` чист |

## Известные ограничения (честно)

* Это самопроверка, **не пентест**. Реальные клиенты Telegram, реальный Android/Termux и живые MRKT/Telegram-рынок в проверке **не участвовали**.
* Скрипт `telegram-web-app.js` грузится с `telegram.org` без SRI-хэша: так требует Telegram (файл обновляется на месте), риск ограничен политикой CSP (скрипты только с нашего домена и `telegram.org`).
* Подпись входа в мини-приложение действует 24 часа (`WEBAPP_AUTH_MAX_AGE`); перехват возможен только при взломе TLS.
* Лимит запросов хранится в памяти процесса и рассчитан на один экземпляр. Анонимный поток запросов на статику ничем, кроме Cloudflare, не ограничен.
* База SQLite и строка сессии не шифруются на диске (защита файловой системой Android).
* Quick-туннель Cloudflare бесплатный, без гарантий и без собственной авторизации; для постоянной работы используйте домен и Caddy.
* Любая сторонняя биржа может изменить API или заблокировать клиента; бот при этом отступает и не обходит защиту.

## Что сделать вам (по важности)

1. **Отозвать токен бота** (`/revoke` в @BotFather) и внести новый только в `.env` на планшете.
2. Для реального рынка использовать **отдельный аккаунт Telegram** без подарков и денег, включить на нём двухфакторную защиту.
3. Держать планшет заблокированным; не давать Termux доступ к общему хранилищу без необходимости.
4. Очищать буфер обмена клавиатуры после вставки секретов; не отправлять скриншоты с секретами.
5. Раз в месяц: `git pull`, `pip install -U -r requirements-termux.txt`, `pip-audit`.
