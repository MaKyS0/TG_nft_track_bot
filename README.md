# NFT Tracker

Telegram-бот, который следит за маркетплейсом улучшенных (upgraded) подарков и присылает уведомления, когда появляется предложение под ваши фильтры.

Стек: Python 3.12, aiogram 3, aiohttp (мини-приложение), PostgreSQL (SQLAlchemy 2 async), Redis (хранилище FSM), Telethon (MTProto-источник), Docker.

> Подробный разбор ограничений Telegram и архитектуры: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что работает, а что нет

| | Статус |
|---|---|
| Интерфейс (🎁 🔔 ⚙️ 📊 ❓), `/start`, фильтры (коллекция, модель, фон, символ, цена в Stars, редкость), вкл/выкл уведомлений, статистика | ✅ работает, покрыто тестами |
| Уведомления без дублей (`UNIQUE(user, offer)`), baseline при первом опросе, лимиты исходящих сообщений, обработка блокировки бота | ✅ работает, покрыто тестами |
| Мини-приложение (вкладки «Лоты», «Фильтры», «Профиль»): API и интерфейс | ✅ работает и проверено в браузере (Chromium, тёмная и светлая темы); **в самом Telegram не открывалось**: нужен публичный HTTPS-адрес, см. ниже |
| Источник `mock` (фейковые данные для проверки бота) | ✅ работает «из коробки» |
| Источник `telegram` (официальный рынок Telegram) | ⚠️ реализован по документированному MTProto-API, парсер проверен на настоящих TL-типах Telethon, **но требует вашего служебного аккаунта и не проверялся на живом Telegram** |
| Источник `mrkt` | ⚠️ экспериментальный, реализован по исходникам сторонних клиентов (документации нет), проверен на макете сервера, **не на живом MRKT** |
| Tonnel | ❌ не подключён: защищён Cloudflare, обход защиты я не делаю (подробнее ниже) |
| Мгновенные уведомления | ❌ невозможны: у Telegram нет push о новых лотах, бот опрашивает рынок по расписанию |
| Владелец подарка | ⚠️ только публичный `@username` из ответа API; иначе имя или «скрыт» |
| Покупка / сделка | ❌ бот сделок не проводит, даёт ссылку `https://t.me/nft/<slug>`; покупка — в самом Telegram |

**Почему нужен MTProto.** Bot API не имеет методов для просмотра лотов перепродажи. Единственный официальный способ — MTProto-метод `payments.getResaleStarGifts`, доступный пользовательскому аккаунту. Бот использует **один служебный аккаунт оператора** (ваш). Аккаунты пользователей бота не нужны, коды входа и пароли пользователей не запрашиваются и не хранятся.

## Быстрый старт (демо с mock-данными)

### 1. Создайте бота в BotFather

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Введите имя (отображаемое) и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AA...`. Это секрет: не публикуйте и не коммитьте его.
4. По желанию: `/setcommands` → `start - Начать`, `help - Помощь`, `cancel - Отмена`; `/setdescription`, `/setuserpic`.
5. Если токен утёк: `/revoke` в BotFather и обновите `.env`.

### 2. Запуск в Docker

```bash
cp .env.example .env
# впишите BOT_TOKEN и замените POSTGRES_PASSWORD (без спецсимволов @ : / ? #)
docker compose up -d --build
docker compose logs -f bot
```

Откройте бота в Telegram → `/start` → «⚙️ Настройки фильтров» → «➕ Новый фильтр». В режиме `mock` новые демо-лоты появляются каждые ~минуту (интервал `POLL_INTERVAL_SECONDS`); первый проход по коллекции только запоминает лоты, уведомления начнутся со второго.

### 3. Запуск без Docker

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
# нужен PostgreSQL; для быстрой проверки подойдёт SQLite:
export BOT_TOKEN=... DATABASE_URL=sqlite+aiosqlite:///./gifts.db
python -m app
```

## Источники данных (рынки)

`GIFT_SOURCE` принимает список через запятую: `mock`, `telegram`, `mrkt` (например, `telegram,mrkt`).

| Источник | Статус | Что нужно |
|---|---|---|
| `mock` | ✅ работает, но данные **выдуманные** | ничего |
| `telegram` | ⚠️ официальный MTProto-API (`payments.getResaleStarGifts`); парсер проверен на настоящих типах Telethon, **на живом Telegram не запускался** | служебный аккаунт Telegram, `api_id`/`api_hash` |
| `mrkt` | ⚠️ **экспериментальный**: у MRKT нет документации, протокол взят из открытых клиентов `amrkt`/`mrkts`; проверен на макете сервера, **не на живом MRKT** | то же, что для `telegram` (вход в MRKT идёт через тот же аккаунт) |
| Tonnel | ❌ **не подключён** | см. ниже |

**Почему нет Tonnel.** API Tonnel защищён Cloudflare: обычный запрос получает `403`. Известные клиенты проходят защиту, выдавая себя за браузер (подмена TLS-отпечатка и User-Agent). Это обход защиты от ботов: он нарушает правила сервиса, а ваш аккаунт могут заблокировать. Я такое не реализую. Если у Tonnel появится официальный доступ или ключ, достаточно написать ещё один класс `GiftSource` (см. `app/sources/mrkt.py` как образец).

**Как работает MRKT.** Служебный аккаунт открывает мини-приложение MRKT (`t.me/mrkt/app`), Telegram выдаёт подписанный `initData`, MRKT меняет его на токен, затем бот запрашивает лоты коллекций (`POST /gifts/saling`). Цены в TON; фильтры «Цена от/до, TON» работают только для них. Продавец не раскрывается, в карточке есть кнопка «Купить на MRKT». Бот опрашивает MRKT бережно (пауза `MRKT_REQUEST_DELAY`, честный User-Agent), на `429` и `403` отступает и **не** пытается обойти защиту. Ссылка на страницу подарка строится по правилу Telegram (`t.me/nft/<Коллекция>-<номер>`): для MRKT проверить её на живых данных не удалось.

**Картинка подарка.** В карточках мини-приложения и в уведомлениях показывается готовое изображение подарка (фон, узор и сам подарок вместе). Оно берётся с публичного CDN Fragment по `slug` (`nft.fragment.com/gift/<slug>.medium.jpg`). Если картинка недоступна, карточка остаётся с цветной шапкой, а уведомление уходит текстом. Побочный эффект: Fragment видит IP-адрес устройства, которое показывает картинку.

**Прямая ссылка на подарок в MRKT.** У MRKT нет документированной ссылки на конкретный подарок, поэтому по умолчанию кнопка «Купить на MRKT» открывает приложение MRKT (`https://t.me/mrkt/app`). Если вы узнаете настоящий формат (в MRKT откройте подарок → «Поделиться» → скопируйте ссылку), задайте его шаблоном в `.env`, например:

```
MRKT_LINK_TEMPLATE=https://t.me/mrkt/app?startapp={id}
```

Доступны подстановки `{id}` (идентификатор лота в MRKT), `{slug}` и `{number}`. Шаблон обязан начинаться с `https://t.me/mrkt`, прочие скобки запрещены; значения проверяются по набору символов. Если у лота нет подходящего `id`, бот вернётся к ссылке на приложение.

**Подключение (Termux):**

```bash
bash scripts/termux_login.sh   # спросит api_id/api_hash (скрыто), выполнит вход и включит рынки
bash scripts/termux_run.sh
```

**Подключение (вручную / Docker):**

1. Заведите **отдельный** аккаунт Telegram без ценных подарков и включите на нём двухфакторную защиту.
2. На <https://my.telegram.org> → *API development tools* получите `api_id` и `api_hash`, впишите в `.env` (`TG_API_ID`, `TG_API_HASH`).
3. Локально выполните `python scripts/make_session.py`: вход (телефон, код, пароль 2FA) вводится в терминале, а строка сессии пишется прямо в `.env` и **нигде не печатается**.
4. В `.env`: `GIFT_SOURCE=telegram` (или `telegram,mrkt`).
5. В логе должно появиться `Telegram account connected` и `Catalog refreshed: N collections`.

Строка сессии даёт полный доступ к аккаунту: не коммитьте `.env`, не присылайте его и не фотографируйте. Подробнее: [docs/SECURITY.md](docs/SECURITY.md).

Правила и лимиты:

* Опрашиваются только коллекции, нужные активным фильтрам (если у кого-то фильтр без коллекции, то все). Между запросами пауза `SOURCE_REQUEST_DELAY`; при `FloodWait` опрос приостанавливается на указанное Telegram время.
* Цикл по ~100 коллекциям при паузе 1,5 с занимает несколько минут, поэтому уведомления приходят с задержкой.
* За каждую коллекцию берётся первая страница (`LISTINGS_PER_COLLECTION`) самых свежих лотов; у MRKT до `MRKT_MAX_PAGES` страниц по `MRKT_PAGE_SIZE`, отсортированных по цене (порядок «новые первыми» для MRKT мне неизвестен).
* Первый проход по каждой паре «коллекция + рынок» только запоминает лоты: подключение нового рынка к работающему боту не засыпает уведомлениями о старых лотах.
* Автоматизация пользовательского аккаунта подпадает под [Telegram API Terms](https://core.telegram.org/api/terms). Не снижайте паузы, используйте отдельный аккаунт.

## Мини-приложение (Telegram Mini App)

Веб-интерфейс внутри Telegram: лоты по вашим фильтрам с карточками в цветах фона подарка, редактор фильтров, переключатель уведомлений, статистика. Работает на тех же данных, что и бот, отдельной регистрации нет: пользователя определяет подпись `initData`, которую Telegram передаёт приложению (проверка по [официальному алгоритму](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), токен бота подписи не раскрывает).

Telegram открывает мини-приложения **только по HTTPS**, поэтому нужен публичный адрес.

**Вариант 1. Свой домен (для постоянной работы).** Направьте A-запись домена на сервер, откройте порты 80 и 443, затем в `.env`:

```
DOMAIN=app.example.com
WEBAPP_URL=https://app.example.com
```

```bash
docker compose --profile https up -d --build
```

Caddy сам получит и будет продлевать сертификат.

**Вариант 2. Быстрая проверка без домена.** Туннель Cloudflare выдаёт временный https-адрес:

```bash
cloudflared tunnel --url http://localhost:8080
# в .env: WEBAPP_URL=https://что-то-выданное.trycloudflare.com
docker compose up -d --build
```

После запуска бот сам: ставит кнопку меню рядом с полем ввода, добавляет в клавиатуру кнопку «📱 Мини-приложение» и выставляет имя, описание и краткое описание профиля (только если они отличаются от заданных, `BOT_NAME` в `.env`).
Необязательно: в @BotFather → `/newapp` можно создать прямую ссылку вида `t.me/<бот>/<приложение>`.

Безопасность: API принимает только запросы с валидной и свежей (`WEBAPP_AUTH_MAX_AGE`) подписью; пользователь видит и меняет только свои фильтры; страница отдаётся с `Content-Security-Policy` (скрипты только с собственного домена и `telegram.org`); весь пользовательский текст выводится через `textContent`.

## Обновление существующей установки

Миграций пока нет (`create_all` не меняет существующие таблицы). Если база создана до появления мини-приложения, добавьте колонки цветов фона:

```sql
ALTER TABLE listings ADD COLUMN backdrop_center INTEGER, ADD COLUMN backdrop_edge INTEGER;
```

(или удалите таблицу `listings`: она пересоздастся, а лоты будут накоплены заново.)

## Фильтры

Лот подходит, если выполнены **все** заданные условия одного активного фильтра; пустое поле — «любое».

| Параметр | Как задаётся |
|---|---|
| Коллекция, модель, фон, символ | название целиком, без учёта регистра (`plush pepe` = `Plush Pepe`) |
| Мин./макс. цена, Stars | целое число; относится только к лотам в Stars (Telegram) |
| Мин./макс. цена, TON | число с точкой или запятой, до 4 знаков (`12.5`); относится только к лотам в TON (MRKT). Если в фильтре заданы границы только в одной валюте, лоты в другой валюте под него не попадают |
| Редкость | порог в промилле (1–1000): подойдёт лот, у которого модель, фон или символ не реже этого порога (`20` = 2%) |

Сброс значения — отправить `-`. До 10 фильтров на пользователя (`MAX_FILTERS_PER_USER`).

## Запуск на Android (Termux): бот и мини-приложение без сервера

Подойдёт, чтобы попробовать всё с планшета или телефона: SQLite вместо PostgreSQL, Redis не нужен, публичный HTTPS-адрес даёт бесплатный туннель Cloudflare.

1. Установите **Termux из F-Droid** (версия из Google Play устарела, `pkg` в ней не работает).
2. В Termux:
   ```bash
   pkg install -y git
   git clone -b claude/magical-clarke-1aww4p https://github.com/MaKyS0/TG_nft_track_bot
   cd TG_nft_track_bot
   bash scripts/termux_setup.sh   # ставит пакеты и зависимости, спросит токен бота (ввод скрыт)
   bash scripts/termux_run.sh     # туннель + бот; остановка: Ctrl+C
   ```
3. В боте нажмите `/start`: появится кнопка «📱 Мини-приложение».

Что нужно знать:

* Первая установка долгая: `pydantic-core` собирается из исходников (10-20 минут, нужен заряд и Wi-Fi).
* Адрес туннеля меняется при каждом запуске, бот сам переустанавливает кнопку меню. Пока `termux_run.sh` не запущен, мини-приложение недоступно.
* Android усыпляет фоновые приложения: оставьте Termux открытым или в уведомлении нажмите «Acquire wakelock» (скрипт делает это сам), а в настройках батареи отключите для Termux оптимизацию.
* Токен вводится в Termux, а не пишется в чат. Если репозиторий приватный, `git clone` попросит вход (логин GitHub и персональный токен вместо пароля).
* По умолчанию включён режим `mock` (демо-данные). Реальные рынки включает `bash scripts/termux_login.sh` (см. раздел «Источники данных»).
* Скрипты проверены на имитации (подмена `cloudflared`) и набор тестов проходит с зависимостями из `requirements-termux.txt`, но на реальном Android я их не запускал.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Покрыто: логика фильтров, валидация ввода, форматирование, разбор ответов Telethon (на реальных TL-типах), монитор (baseline, дедупликация, смена цены, несколько фильтров, блокировка, ошибки источника, FloodWait), сквозные сценарии бота через `Dispatcher`, проверка подписи `initData` и все эндпоинты API мини-приложения. По умолчанию тесты идут на SQLite. Чтобы прогнать их на PostgreSQL (БД очищается перед каждым тестом, берите одноразовую):

```bash
TEST_DATABASE_URL=postgresql+asyncpg://user:pass@localhost:5432/gifts_test pytest
```

Набор проходит на обеих СУБД (запросы совместимы: `INSERT … ON CONFLICT … RETURNING`).

## Безопасность

Полный разбор (что проверено, что нет, что делать вам): [docs/SECURITY.md](docs/SECURITY.md).

Кратко:


* Секреты только в `.env` (в `.gitignore`), токен маскируется в логах.
* Бот хранит Telegram ID, username, имя и фильтры пользователей; никаких паролей, кодов входа и сессий пользователей.
* Контейнер работает от непривилегированного пользователя.

## Ограничения и план развития

* Схема БД создаётся через `create_all`; перед изменением схемы в продакшене подключите Alembic.
* Один процесс-монитор; для горизонтального масштабирования нужен advisory-lock в БД.
* Сопоставление лотов с фильтрами идёт в Python; для десятков тысяч фильтров стоит перенести в SQL.
* Идеи: фильтры по номеру подарка, уведомления о падении цены, дополнительные источники через интерфейс `GiftSource` (только легальные и документированные).
