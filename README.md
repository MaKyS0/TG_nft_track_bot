# Gift Track Bot

Telegram-бот, который следит за маркетплейсом улучшенных (upgraded) подарков и присылает уведомления, когда появляется предложение под ваши фильтры.

Стек: Python 3.12, aiogram 3, PostgreSQL (SQLAlchemy 2 async), Redis (хранилище FSM), Telethon (MTProto-источник), Docker.

> Подробный разбор ограничений Telegram и архитектуры: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что работает, а что нет

| | Статус |
|---|---|
| Интерфейс (🎁 🔔 ⚙️ 📊 ❓), `/start`, фильтры (коллекция, модель, фон, символ, цена в Stars, редкость), вкл/выкл уведомлений, статистика | ✅ работает, покрыто тестами |
| Уведомления без дублей (`UNIQUE(user, offer)`), baseline при первом опросе, лимиты исходящих сообщений, обработка блокировки бота | ✅ работает, покрыто тестами |
| Источник `mock` (фейковые данные для проверки бота) | ✅ работает «из коробки» |
| Источник `telethon` (реальный рынок) | ⚠️ реализован по документированному MTProto-API (`payments.getStarGifts`, `payments.getResaleStarGifts`), парсер проверен на настоящих TL-типах Telethon, **но требует вашего служебного аккаунта и не проверялся на живом Telegram** |
| Мгновенные уведомления | ❌ невозможны: у Telegram нет push о новых лотах, бот опрашивает рынок по расписанию |
| Владелец подарка | ⚠️ только публичный `@username` из ответа API; иначе имя или «скрыт» |
| Покупка / сделка | ❌ бот сделок не проводит, даёт ссылку `https://t.me/nft/<slug>`; покупка — в самом Telegram |

**Почему нужен MTProto.** Bot API не имеет методов для просмотра лотов перепродажи. Единственный официальный способ — MTProto-метод `payments.getResaleStarGifts`, доступный пользовательскому аккаунту. Бот использует **один служебный аккаунт оператора** (ваш). Аккаунты пользователей бота не нужны, коды входа и пароли пользователей не запрашиваются и не хранятся.

## Быстрый старт (демо с mock-данными)

### 1. Создайте бота в BotFather

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Введите имя (отображаемое) и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AA...`. Это секрет: не публикуйте и не коммитьте его.
4. По желанию: `/setcommands` → `start - Начать`, `help - Помощь`, `cancel - Отмена`; `/setdescription`, `/setuserpic`.
5. Если токен утёк: `/revoke` в BotFather и обновите `.env`.

### 2. Запуск в Docker

```bash
cp .env.example .env
# впишите BOT_TOKEN и замените POSTGRES_PASSWORD (без спецсимволов @ : / ? #)
docker compose up -d --build
docker compose logs -f bot
```

Откройте бота в Telegram → `/start` → «⚙️ Настройки фильтров» → «➕ Новый фильтр». В режиме `mock` новые демо-лоты появляются каждые ~минуту (интервал `POLL_INTERVAL_SECONDS`); первый проход по коллекции только запоминает лоты, уведомления начнутся со второго.

### 3. Запуск без Docker

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
# нужен PostgreSQL; для быстрой проверки подойдёт SQLite:
export BOT_TOKEN=... DATABASE_URL=sqlite+aiosqlite:///./gifts.db
python -m app
```

## Подключение реального рынка (`GIFT_SOURCE=telethon`)

1. Заведите **отдельный** аккаунт Telegram для бота-наблюдателя (не личный).
2. На <https://my.telegram.org> → *API development tools* создайте приложение и получите `api_id` и `api_hash`.
3. Локально (не на сервере, не в CI) получите строку сессии:
   ```bash
   pip install telethon
   TG_API_ID=12345 TG_API_HASH=abcdef... python scripts/make_session.py
   ```
   Скрипт спросит телефон, код и пароль 2FA **в вашем терминале** и напечатает `TG_SESSION_STRING=...`.
4. В `.env`: `GIFT_SOURCE=telethon`, `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_STRING`.
   Строка сессии даёт полный доступ к аккаунту, храните её как пароль.
5. `docker compose up -d --build`. В логе должно появиться `Telethon source connected` и `Catalog refreshed: N collections`.

Правила и лимиты:

* Опрашиваются только коллекции, которые нужны активным фильтрам (если у кого-то фильтр без коллекции — все). Между запросами пауза `SOURCE_REQUEST_DELAY`; при `FloodWait` опрос приостанавливается на указанное Telegram время.
* Цикл по ~100 коллекциям при паузе 1,5 с занимает несколько минут, поэтому уведомления приходят с задержкой.
* За каждую коллекцию берётся первая страница (`LISTINGS_PER_COLLECTION`, по умолчанию 50) самых свежих лотов. Редкие лоты старше первой страницы не видны.
* Автоматизация пользовательского аккаунта подпадает под [Telegram API Terms](https://core.telegram.org/api/terms). Не снижайте паузы и используйте отдельный аккаунт.

## Фильтры

Лот подходит, если выполнены **все** заданные условия одного активного фильтра; пустое поле — «любое».

| Параметр | Как задаётся |
|---|---|
| Коллекция, модель, фон, символ | название целиком, без учёта регистра (`plush pepe` = `Plush Pepe`) |
| Мин./макс. цена | целое число Stars; лоты, выставленные в TON, под ценовые фильтры не попадают |
| Редкость | порог в промилле (1–1000): подойдёт лот, у которого модель, фон или символ не реже этого порога (`20` = 2%) |

Сброс значения — отправить `-`. До 10 фильтров на пользователя (`MAX_FILTERS_PER_USER`).

## Конфигурация

Все параметры — в `.env` (см. [.env.example](.env.example)).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | токен от BotFather |
| `DATABASE_URL` | — | `postgresql+asyncpg://user:pass@host/db` (в compose подставляется автоматически) |
| `REDIS_URL` | пусто | FSM-хранилище; пусто = в памяти |
| `GIFT_SOURCE` | `mock` | `mock` или `telethon` |
| `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_STRING` | — | для `telethon` |
| `POLL_INTERVAL_SECONDS` | 60 | пауза между циклами опроса |
| `SOURCE_REQUEST_DELAY` | 1.5 | пауза между запросами к Telegram |
| `LISTINGS_PER_COLLECTION` | 50 | глубина опроса одной коллекции |
| `CATALOG_TTL_SECONDS` | 900 | как часто обновлять список коллекций |
| `SEARCH_FRESH_MINUTES` | 30 | «Найти подарки» показывает лоты, замеченные за этот период |
| `MAX_FILTERS_PER_USER` | 10 | лимит фильтров |
| `NOTIFY_RATE_PER_SECOND` | 20 | глобальный лимит отправки (у Telegram ≈30/с) |
| `LOG_LEVEL` | INFO | уровень логов |

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Покрыто: логика фильтров, валидация ввода, форматирование, разбор ответов Telethon (на реальных TL-типах), монитор (baseline, дедупликация, смена цены, несколько фильтров, блокировка, ошибки источника, FloodWait), сквозные сценарии бота через `Dispatcher`. По умолчанию тесты идут на SQLite. Чтобы прогнать их на PostgreSQL (БД очищается перед каждым тестом, берите одноразовую):

```bash
TEST_DATABASE_URL=postgresql+asyncpg://user:pass@localhost:5432/gifts_test pytest
```

Набор проходит на обеих СУБД (запросы совместимы: `INSERT … ON CONFLICT … RETURNING`).

## Безопасность

* Секреты только в `.env` (в `.gitignore`), токен маскируется в логах.
* Бот хранит Telegram ID, username, имя и фильтры пользователей; никаких паролей, кодов входа и сессий пользователей.
* Контейнер работает от непривилегированного пользователя.

## Ограничения и план развития

* Схема БД создаётся через `create_all`; перед изменением схемы в продакшене подключите Alembic.
* Один процесс-монитор; для горизонтального масштабирования нужен advisory-lock в БД.
* Сопоставление лотов с фильтрами идёт в Python; для десятков тысяч фильтров стоит перенести в SQL.
* Идеи: фильтры по номеру подарка, уведомления о падении цены, дополнительные источники через интерфейс `GiftSource` (только легальные и документированные).
